Running `claude` inside an existing Claude Code session or agent harness normally triggers nested-session guards. One-shot `claude-p` strips those parent markers automatically without disturbing authentication or cloud-provider configuration.

## What `buildChildEnv` strips vs. preserves

In `src/driver.zig`, `shouldStripChildEnv()` strips **only** nested-session and parent-agent markers:

| Action | Environment variables |
| --- | --- |
| **Stripped (exact)** | `CLAUDECODE`, `AI_AGENT`, `CLAUDE_CODE_ENTRYPOINT`, `CLAUDE_CODE_SSE_PORT`, `CLAUDE_CODE_CHILD_SESSION`, `CLAUDE_CODE_SESSION_ID` |
| **Stripped (prefix)** | `CLAUDE_CODE_SESSION_*`, `CLAUDE_CODE_PARENT_*`, `CLAUDE_CODE_SUBAGENT_*` |
| **Preserved** | `CLAUDE_CODE_OAUTH_TOKEN`, `CLAUDE_CODE_USE_BEDROCK`, `CLAUDE_CODE_USE_VERTEX`, `CLAUDE_CODE_USE_FOUNDRY`, `CLAUDE_CONFIG_DIR`, `ANTHROPIC_API_KEY`, and all other user env vars |
| **Injected / defaulted** | `CLAUDE_P_FIFO=<per-run FIFO path>`, `TERM=xterm-256color`, and `CLAUDE_CODE_FORCE_SESSION_PERSISTENCE=1` (unless already set) |

Because `CLAUDE_CODE_*` is **not** blanket-stripped, Bedrock, Vertex, Foundry, and OAuth sessions work out of the box:

```bash
CLAUDE_CODE_USE_VERTEX=1 \
CLOUD_ML_REGION=us-east5 \
ANTHROPIC_VERTEX_PROJECT_ID=my-gcp-project \
  npx claude-p --dangerously-skip-permissions "Reply OK."
```

## Non-interactive permissions in CI

`claude-p` does not proxy interactive tool-approval dialogs to your shell. For headless automation, choose one of:

- `--dangerously-skip-permissions` — bypasses all tool permission prompts (and `claude-p` automatically accepts Claude Code's bypass-permissions confirmation modal).
- `--permission-mode <mode>` — passes a permission mode such as `acceptEdits`, `plan`, or `dontAsk`.
- `--allowedTools <list>` / `--disallowedTools <list>` — restricts which tools `claude` may run without prompting.

```bash
npx claude-p \
  --permission-mode dontAsk \
  --allowedTools "Read,Grep,Glob" \
  --output-format json \
  "Find all TODO comments in src/."
```

## Daemon mode note

`src/daemon.zig` currently copies the parent process environment verbatim (appending `CLAUDE_P_FIFO` and `TERM=xterm-256color`) rather than calling `driver.buildChildEnv`. When launching `claude-p daemon` from inside another Claude Code session, unset `CLAUDECODE` and `AI_AGENT` in the caller:

```bash
env -u CLAUDECODE -u AI_AGENT npx claude-p daemon --dangerously-skip-permissions
```
