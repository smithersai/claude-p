**Goal:** Add `claude_p` to a Zig **0.15.2** executable, run a one-shot prompt, stream live JSONL lines to a custom writer, and merge library-level `extra_hooks` and `extra_settings_json` without touching `~/.claude/`.

**Time:** 10 minutes. You need Zig **0.15.2** (`zmux` enforces `0.15.2` at comptime) and `claude` on `$PATH`.

---

## Step 1: Fetch `claude_p` and wire `build.zig`

In your Zig project directory, fetch the package:

```bash
zig fetch --save=claude_p git+https://github.com/smithersai/claude-p
```

Then import the `claude_p` module and add a `run` step in `build.zig`:

```zig
const std = @import("std");

pub fn build(b: *std.Build) void {
    const target = b.standardTargetOptions(.{});
    const optimize = b.standardOptimizeOption(.{});

    const claude_p_dep = b.dependency("claude_p", .{
        .target = target,
        .optimize = optimize,
    });

    const exe = b.addExecutable(.{
        .name = "my-agent",
        .root_module = b.createModule(.{
            .root_source_file = b.path("src/main.zig"),
            .target = target,
            .optimize = optimize,
            .link_libc = true,
            .imports = &.{
                .{ .name = "claude_p", .module = claude_p_dep.module("claude_p") },
            },
        }),
    });
    b.installArtifact(exe);

    const run_cmd = b.addRunArtifact(exe);
    run_cmd.step.dependOn(b.getInstallStep());
    if (b.args) |args| run_cmd.addArgs(args);
    const run_step = b.step("run", "Run my-agent");
    run_step.dependOn(&run_cmd.step);
}
```

<Callout title="No system libraries to link" kind="concept">
  <code>claude_p</code> embeds <code>zmux.NativeSession</code>, which needs <code>libc</code>,
  <code>libutil</code> on Linux (<code>openpty</code>/<code>forkpty</code>), and
  <code>libproc</code> on macOS. The exported <code>claude_p</code> module already declares those
  in claude-p's <code>build.zig</code>, so your executable links them through the import. Do not
  add your own <code>linkSystemLibrary</code> calls.
</Callout>

## Step 2: Run your first prompt from Zig

Replace `src/main.zig` with a minimal one-shot call:

```zig
const std = @import("std");
const claude_p = @import("claude_p");

pub fn main() !void {
    var gpa: std.heap.GeneralPurposeAllocator(.{}) = .{};
    defer _ = gpa.deinit();
    const alloc = gpa.allocator();

    var result = try claude_p.run(alloc, .{
        .prompt = "What is the capital of France? Reply with one word.",
        .output_format = .text,
        .skip_permissions = true,
        .timeout_ms = 60_000,
    });
    defer result.deinit(alloc);

    std.debug.print("answer: {s}\n", .{result.summary.final_text});
    std.debug.print("session: {s}\n", .{result.summary.session_id});
    std.debug.print("tokens: in={d} out={d} ({d} ms)\n", .{
        result.summary.usage.input_tokens,
        result.summary.usage.output_tokens,
        result.duration_ms,
    });
}
```

Build and run through the `run` step, or run the installed binary directly:

```bash
zig build run
# or
zig build && ./zig-out/bin/my-agent
```

Notice the ownership contract: `claude_p.run` takes an explicit `std.mem.Allocator` and returns a `Result` whose `Summary` owns `final_text`, `session_id`, and `jsonl_replay`. Always pair it with `defer result.deinit(alloc);`.

## Step 3: Stream live lines + attach custom hooks

You can combine **`stream_writer`** (live per-message streaming straight into any `std.Io.Writer`) with inline hook and settings merging (**`extra_hooks`** and **`extra_settings_json`**, also available on the CLI via `--extra-hook` and `--setting-json`) without touching `~/.claude/`.

Update `src/main.zig`:

```zig
const std = @import("std");
const claude_p = @import("claude_p");

pub fn main() !void {
    var gpa: std.heap.GeneralPurposeAllocator(.{}) = .{};
    defer _ = gpa.deinit();
    const alloc = gpa.allocator();

    var stdout_buf: [4096]u8 = undefined;
    var stdout_writer = std.fs.File.stdout().writer(&stdout_buf);
    const stdout = &stdout_writer.interface;

    var result = try claude_p.run(alloc, .{
        .prompt = "Reply with the single word OK.",
        .output_format = .stream_json,
        .verbose = true,
        .skip_permissions = true,
        .stream_writer = stdout,
        // Appended AFTER claude-p's relay hooks (relay stays index 0).
        .extra_hooks = &.{
            .{ .event = "Stop", .command = "echo 'turn finished' >&2" },
        },
        // Top-level keys merged into --settings; any "hooks" key here is ignored.
        .extra_settings_json = "{\"cleanupPeriodDays\":7}",
    });
    defer result.deinit(alloc);

    // Safe to call even in stream_json mode: Result.write is a no-op
    // when result.streamed == true so nothing is double-emitted.
    try result.write(alloc, stdout, .stream_json);
    try stdout.flush();
}
```

<Callout title="Watch the bytes: how extra_hooks stays safe" kind="bytes">
  In <code>src/hook.zig</code>, <code>createWithOptions()</code> validates
  <code>extra_hooks</code> and <code>extra_settings_json</code> <em>before</em> creating the temp
  directory or FIFO. Invalid JSON, non-object JSON, JSON nested deeper than 128 levels,
  <code>"disableAllHooks": true</code>, or empty hook strings fail immediately with
  <code>error.InvalidExtraSettings</code> and leave zero temp files behind. And
  <code>claude-p</code>'s own relay hooks are always inserted first so your hooks can never break
  <code>SessionStart</code> or <code>Stop</code> detection.
</Callout>

<Callout title="Mental check: why didn't Result.write print twice?" kind="check">
  When <code>output_format == .stream_json</code> and <code>stream_writer != null</code>,
  <code>driver.run()</code> tails lines live, emits the trailing <code>result</code> envelope, and
  sets <code>result.streamed = true</code>. <code>Result.write()</code> checks
  <code>if (self.streamed and fmt == .stream_json) return;</code> so callers can use one unified
  emit path for all three formats.
</Callout>

    <code>error.InvalidExtraSettings</code> is returned only for malformed JSON, a non-object root

    non-UTF-8 <code>ExtraHook.event</code>/<code>command</code>.

## There are no dumb questions

**Q: Why does `build.zig` fail if I run Zig 0.16 or 0.17?**
**A:** `zmux` checks the compiler version at `comptime` and pins Zig **`0.15.2`**. Use `zvm use 0.15.2` (or point your CI action at `0.15.2`) when building or embedding `claude_p`.

**Q: Who frees `result.summary.final_text`, `session_id`, and `jsonl_replay`?**
**A:** Your allocator. Every public function in `claude_p` follows allocator-per-function ownership; calling `defer result.deinit(alloc);` frees all three heap buffers.
