`claude-p` treats Claude Code's own hook system and session JSONL log as the source of truth for lifecycle state and assistant output.

## Per-run hook harness (`src/hook.zig`)

Each invocation creates a private directory under `$TMPDIR` (falling back to `/tmp`):

```text
$TMPDIR/claude-p-<pid>-<rand>/
├── events.fifo   (mode 0600, named pipe)
└── hook.sh       (mode 0700, POSIX /bin/sh relay)
```

`hook.sh` reads the hook's JSON payload from stdin and appends one tab-delimited line to `$CLAUDE_P_FIFO`:

```sh
#!/bin/sh
set -eu
event="$1"
fifo="${CLAUDE_P_FIFO:?missing CLAUDE_P_FIFO}"
payload="$(cat)"
printf '%s\t%s\n' "$event" "$payload" >> "$fifo"
exit 0
```

`hook.createWithOptions()` serializes an inline `--settings` JSON object registering `hook.sh` at index `0` for `SessionStart`, `UserPromptSubmit`, and `Stop` (with matcher `"*"`). Paths containing spaces or shell metacharacters are single-quoted automatically.

When `HookHarness.deinit()` runs via `defer`, the FIFO, script, and temp directory are deleted. `~/.claude/` is never modified.

### Why `events.fifo` opens before spawning `claude`

On POSIX systems, opening a FIFO for writing blocks until a reader has opened it. Both `driver.zig` and `daemon.zig` open `events.fifo` with `O_RDONLY | O_NONBLOCK` **before** calling `zmux.NativeSession.create()`. That guarantees a reader fd is present from millisecond zero so `hook.sh` never blocks.

## Live `pread` tailing (`src/stream.zig`)

In `stream-json` mode and daemon mode, `stream.Tailer` tails Claude's live session JSONL file:

- Uses `std.posix.pread(fd, buf, self.pos)` instead of `read()` so it maintains its own cursor without disturbing file offsets.
- Appends bytes into an internal `partial` buffer and writes to the caller's writer **only** up to complete `\n` boundaries—never emitting torn JSON lines.
- Non-blocking: when no new bytes exist, `pump()` returns `0`.

## The `Stop`-vs-flush race and resume isolation

Empirically, Claude Code can fire the `Stop` hook a few milliseconds before the final `assistant` JSONL line finishes flushing to disk.

<ResumeOffsetDiagram />

`driver.run()` handles both the flush race and `--resume` isolation with one mechanism:

1. Before submitting the prompt, it records `pre_prompt_transcript_offset = stat(transcript_path).size`.
2. If `Stop` reports a different `transcript_path` than `SessionStart` did (for example, a new session file created on first turn), the driver resets `pre_prompt_transcript_offset = 0` and reopens the tailer.
3. In `stream-json` mode, it drains the tailer for `20 × 20 ms` (400 ms).
4. It calls `transcript.parseFileFromOffset(alloc, path, pre_prompt_transcript_offset)` up to `20` times at `50 ms` intervals—and up to `30` times total if a candidate parses but its `final_text` disagrees with Stop's `last_assistant_message`.
5. If retries still find no assistant message on disk, it synthesizes a `Summary` directly from Stop's `last_assistant_message` and `session_id` fields. If neither exists, it returns `RunError.TranscriptUnavailable`.

## Transcript parsing details (`src/transcript.zig`)

- Accepts both `sessionId` (real Claude Code transcripts) and `session_id` (legacy stream-json).
- Concatenates all `{"type":"text"}` blocks inside each `assistant` message's `message.content` array; the **last** assistant message wins for `final_text`.
- Sums `input_tokens`, `output_tokens`, `cache_read_input_tokens`, and `cache_creation_input_tokens` across every assistant entry in the parsed byte slice.
- Skips malformed lines (including a torn leading fragment if an offset landed mid-line) without aborting the parse.
- If a `{"type":"result"}` line is present in the slice, its `result`, `is_error`, `num_turns`, `total_cost_usd`, and `duration_api_ms` fields take precedence.
